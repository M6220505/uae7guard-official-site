# V2.6 Upgrade Guide — Platform Modernization

V2.6 upgrades the entire toolchain to the current stable releases (June 2026)
with **no change to product behavior**. All routes, the risk-analysis API, the
admin/tenant security model, i18n (EN/AR + RTL), and the CI gates work exactly
as before — now on a modern, supported stack.

largely by removing the unused RainbowKit + WalletConnect subtree and adopting
wagmi 3's slimmer dependency graph.

## Breaking changes handled

1. **Bundler → Turbopack.** Next.js 16 uses Turbopack by default for `dev` and
   `build`. The old `webpack` alias function in `next.config.ts` was ported to
   `turbopack.resolveAlias` (the `async-storage` / `pino-pretty` stubs are
   preserved).
2. **`eslint` config key removed.** Next.js 16 dropped the built-in `eslint`
   block from `next.config.ts`. Linting is handled by Biome, so the key was
   simply removed.
3. **`middleware.ts` → `proxy.ts`.** Next.js 16 deprecated the `middleware`
   file convention in favor of `proxy`. The file was renamed; next-intl's
   handler signature is unchanged, so the logic is identical.
4. **Framer Motion → Motion.** `framer-motion` is now published as `motion`.
   Imports changed from `from 'framer-motion'` to `from 'motion/react'`. The
   `motion.*` component API is unchanged.
5. **React 19 / TypeScript 6 types.** `@types/react*` bumped to 19; full
   `tsc --noEmit` passes with no source changes required (the code already used
   async `params` and modern patterns).

## Verification (all green on the upgraded stack)

- `npm run build` — compiles via Turbopack, all routes generated
- `npm run typecheck` — TypeScript 6, 0 errors
- `npm run lint` — Biome, 0 findings
- `npm run dataset:validate` / `dataset:evaluate` — engine at 100% precision/recall/F1 on labeled set
- `npm run test:security-smoke` — **10/10 passing** (auth gating, tenant keys,
  rate limits, daily quotas, payload validation, secure session cookie)
- Manual: `/`, `/en`, `/ar`, `/en/dashboard`, `/en/developers`, `/en/usage`
  all return 200; `POST /api/analyze` returns a scored result; admin endpoints
  gate correctly (503 without key in prod, 200 with key).

## Known advisory (not actionable on latest stable)

`npm audit` reports 3 moderate findings for a `postcss` copy bundled **inside
Next.js's own internals** (`node_modules/next/node_modules/postcss`). We are
already on the latest stable Next.js (16.2.7); the only "fix" npm offers is a
destructive downgrade to Next.js 9, so it is intentionally not applied. This
will clear when Vercel ships an updated Next.js patch. The top-level `postcss`
we control is on the patched 8.5.15.
